## 1. Goal

Let a signed-in user **capture** their groceries: create named grocery lists and add, view, edit, and remove the
items on them. This is the first real domain feature of Growcery. It adds basic CRUD exposed as REST endpoints.

### In scope
- CRUD for **grocery lists** owned by the current user.
- CRUD for **items** within a list.
- Per-user data isolation (a user can only see and change their own lists).
- EF Core entities, a migration, and integration tests.

### Out of scope (later specs)
- Sharing lists between users or households.
- Categories, aisles, prices, pantry/stock tracking, and recurring lists.
- Reordering items, bulk operations, and PATCH endpoints.
- Pagination, search, and filtering (lists are expected to be small for now).
- Any frontend.

## 3. Domain model

### 3.1 `GroceryList` (`Models/GroceryList.cs`)

| Property | Type | Rules |
|---|---|---|
| `Id` | `Guid` | PK, generated by the server |
| `OwnerId` | `string` | FK → `AspNetUsers.Id`, required, indexed, **never accepted from the client** |
| `Owner` | `ApplicationUser?` | Navigation |
| `Name` | `string` | Required, 1–100 chars after trimming |
| `CreatedAt` | `DateTimeOffset` | Set to UTC on create |
| `UpdatedAt` | `DateTimeOffset` | Set to UTC on create and on every update, including item changes |
| `Items` | `List<GroceryListItem>` | Navigation. **Cascade delete** |

### 3.2 `GroceryListItem` (`Models/GroceryListItem.cs`)

| Property | Type | Rules |
|---|---|---|
| `Id` | `Guid` | PK, generated by the server |
| `GroceryListId` | `Guid` | FK → `GroceryList.Id`, required, indexed |
| `GroceryList` | `GroceryList?` | Navigation |
| `Name` | `string` | Required, 1–100 chars after trimming (e.g. "Milk") |
| `Quantity` | `decimal?` | Optional, must be > 0 when set. Precision `(10,2)` |
| `Unit` | `string?` | Optional, max 20 chars (e.g. "kg", "L", "pack") |
| `Notes` | `string?` | Optional, max 500 chars |
| `IsPurchased` | `bool` | Defaults to `false` |
| `CreatedAt` | `DateTimeOffset` | Set to UTC on create |
| `UpdatedAt` | `DateTimeOffset` | Set to UTC on create and on every update |

### 3.3 `ApplicationDbContext` changes
- Add `DbSet<GroceryList> GroceryLists` and `DbSet<GroceryListItem> GroceryListItems`.
- In `OnModelCreating`, **call `base.OnModelCreating(builder)` first** (Identity needs it), then configure max
  lengths, decimal precision, indexes on `OwnerId` and `GroceryListId`, and cascade delete from list to items and
  from user to lists.
- Use `DateTimeOffset.UtcNow`. Npgsql maps `DateTimeOffset` to `timestamptz` and rejects values with a non-zero offset.

## 4. API contract

All endpoints:
- Require authentication (`[Authorize]` on the controller).
- Consume and produce `application/json`.
- Scope every query to the current user: `OwnerId == _userManager.GetUserId(User)`.
- Return **`404 Not Found`** (not 403) when a list or item doesn't exist *or* belongs to another user, so the API
  doesn't reveal which IDs exist.

### 4.1 Lists — `GroceryListsController`, route `api/lists`

| Method | Route | Body | Success | Errors |
|---|---|---|---|---|
| `GET` | `/api/lists` | — | `200` `GroceryListSummaryResponse[]` ordered by `UpdatedAt` desc | `401` |
| `GET` | `/api/lists/{id:guid}` | — | `200` `GroceryListResponse` (items included, ordered by `CreatedAt` asc) | `401`, `404` |
| `POST` | `/api/lists` | `CreateGroceryListRequest` | `201` `GroceryListResponse` + `Location` header (`CreatedAtAction`) | `400`, `401` |
| `PUT` | `/api/lists/{id:guid}` | `UpdateGroceryListRequest` | `200` `GroceryListResponse` | `400`, `401`, `404` |
| `DELETE` | `/api/lists/{id:guid}` | — | `204` (the list's items are deleted with it) | `401`, `404` |

### 4.2 Items — `GroceryListItemsController`, route `api/lists/{listId:guid}/items`

| Method | Route | Body | Success | Errors |
|---|---|---|---|---|
| `GET` | `/api/lists/{listId}/items` | — | `200` `GroceryListItemResponse[]` ordered by `CreatedAt` asc | `401`, `404` (list) |
| `GET` | `/api/lists/{listId}/items/{itemId:guid}` | — | `200` `GroceryListItemResponse` | `401`, `404` |
| `POST` | `/api/lists/{listId}/items` | `CreateGroceryListItemRequest` | `201` `GroceryListItemResponse` + `Location` header | `400`, `401`, `404` (list) |
| `PUT` | `/api/lists/{listId}/items/{itemId:guid}` | `UpdateGroceryListItemRequest` | `200` `GroceryListItemResponse` | `400`, `401`, `404` |
| `DELETE` | `/api/lists/{listId}/items/{itemId:guid}` | — | `204` | `401`, `404` |

Any item write (create, update, delete) also sets the parent list's `UpdatedAt`.

### 4.3 Request models (`Models/GroceryListRequests.cs`)

Classes with DataAnnotations, following `AccountViewModels.cs`:

```csharp
public class CreateGroceryListRequest
{
    [Required, StringLength(100, MinimumLength = 1)]
    public string Name { get; set; } = string.Empty;
}

public class UpdateGroceryListRequest       // same shape as Create; PUT replaces the editable fields
{
    [Required, StringLength(100, MinimumLength = 1)]
    public string Name { get; set; } = string.Empty;
}

public class CreateGroceryListItemRequest
{
    [Required, StringLength(100, MinimumLength = 1)]
    public string Name { get; set; } = string.Empty;

    [Range(typeof(decimal), "0.01", "99999999.99")]
    public decimal? Quantity { get; set; }

    [StringLength(20)]
    public string? Unit { get; set; }

    [StringLength(500)]
    public string? Notes { get; set; }
}

public class UpdateGroceryListItemRequest   // full replace of editable fields
{
    [Required, StringLength(100, MinimumLength = 1)]
    public string Name { get; set; } = string.Empty;

    [Range(typeof(decimal), "0.01", "99999999.99")]
    public decimal? Quantity { get; set; }

    [StringLength(20)]
    public string? Unit { get; set; }

    [StringLength(500)]
    public string? Notes { get; set; }

    public bool IsPurchased { get; set; }
}
```

Trim `Name`, `Unit`, and `Notes` before saving. Store blank optional strings as `null`. If `Name` is blank after
trimming, return `400` using `ModelState.AddModelError` + `ValidationProblem()` so the response shape matches the
automatic validation errors.

### 4.4 Response models (`Models/GroceryListResponses.cs`)

`sealed record` types, following `ApiResponseModels.cs`. **Never return EF entities directly.**

## 5. Required change: API-friendly auth responses

By default, Identity's cookie handler **redirects** unauthenticated requests to `/Account/Login` with a `302`. An
API client should get a status code instead. In `Program.cs`, after `AddIdentity(...)`, add:

```csharp
builder.Services.ConfigureApplicationCookie(options =>
{
    options.Events.OnRedirectToLogin = context =>
    {
        context.Response.StatusCode = StatusCodes.Status401Unauthorized;
        return Task.CompletedTask;
    };
    options.Events.OnRedirectToAccessDenied = context =>
    {
        context.Response.StatusCode = StatusCodes.Status403Forbidden;
        return Task.CompletedTask;
    };
});
```

Check that the existing `AccountControllerLoginTests` still pass after this change.

## 8. Test requirements

Add integration tests using `GrowceryWebApplicationFactory`, following `AccountControllerLoginTests.cs`:

- **Each test uses a unique username**, because the factory's InMemory database is shared across tests in a class.
- Authenticate by calling `POST /api/account/register` or `/login` with the factory's client. The default client
  keeps cookies, so later requests on the same client are authenticated.

Minimum cases:

**Lists**
- Unauthenticated `GET /api/lists` returns `401` (not `302`).
- `POST` with a valid name returns `201`, a `Location` header, and a body with the trimmed name.
- `POST` with an empty or whitespace name, or a name over 100 chars, returns `400`.
- `GET /api/lists` returns only the caller's lists, with correct `ItemCount` and `PurchasedCount`.
- `GET /api/lists/{id}` for another user's list returns `404`.
- `PUT` updates the name and advances `UpdatedAt`.
- `DELETE` returns `204`, a following `GET` returns `404`, and the list's items are gone.

**Items**
- `POST` an item to your own list returns `201`. `POST` to another user's list returns `404`.
- `Quantity` of `0` or less returns `400`. Leaving `Quantity` out (`null`) is allowed.
- `PUT` with `IsPurchased = true` persists and is shown in the list summary counts.
- `GET` or `PUT`/`DELETE` of an item using the wrong `listId` (a list the item doesn't belong to) returns `404`.
- `DELETE` returns `204` and updates the parent list's `UpdatedAt`.
